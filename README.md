# Bangers Discovery Data Pipeline

This repo turns passive PowerNap-style activity logs into proactive suggestion
opportunities and the question/answer rows needed to train a user model for
those suggestions.

The pipeline has three broad phases:

1. Build indexed activity data in `logs-indexed/`.
2. Slice the indexed activity into interval rows in `data/`.
3. Run the discovery stages into `discovery_<provider>_<interval>m/`.

At a high level:

```text
../powernap/logs/
  -> staging/*.jsonl
  -> logs-indexed/<connector>/<date>.jsonl
  -> data/log_intervals_<N>m.jsonl
  -> discovery_<provider>_<N>m/01_goals/
  -> discovery_<provider>_<N>m/02a_combined/
  -> discovery_<provider>_<N>m/02b_bridges/
  -> discovery_<provider>_<N>m/02c_suggestion_inputs/
  -> discovery_<provider>_<N>m/03_bangers/
  -> discovery_<provider>_<N>m/04_questions/
  -> discovery_<provider>_<N>m/10_generic_qa/
```

## Prerequisites

- Python 3.11+
- `uv`
- Either `codex` or `claude` on your `PATH`
- Source logs, by default at `../powernap/logs`

Install dependencies:

```bash
uv sync
```

## 1. Build Indexed Logs

Run all indexing stages:

```bash
./scripts/index_all.sh
```

This creates or updates:

```text
staging/
  screen.jsonl
  calendar.jsonl
  email.jsonl
  notifications.jsonl
  filesys.jsonl
  audio.jsonl

logs-indexed/
  screen/<date>.jsonl
  calendar/<date>.jsonl
  ...
  screenshots/
```

Useful environment overrides:

```bash
POWERNAP_LOGS_DIR=/path/to/powernap/logs
STAGING_DIR=/path/to/staging
LOGS_INDEXED_DIR=/path/to/logs-indexed
SCREEN_SCREENSHOTS_DIR=/path/to/labeled_screenshots
```

## 2. Create Interval Records

Discovery runs over interval rows, not directly over the whole logs folder.

```bash
uv run scripts/record_intervals.py 15
```

This writes:

```text
data/log_intervals_15m.jsonl
```

Use another interval size if needed:

```bash
uv run scripts/record_intervals.py 30
```

## 3. Run Discovery

The default output directory is:

```text
discovery_<provider>_<interval>m/
```

For example, with Codex and 15-minute intervals:

```text
discovery_codex_15m/
  01_goals/
  02a_combined/
  02b_bridges/
  02c_suggestion_inputs/
  03_bangers/
  04_questions/
```

Run the stages in order. This example runs the first ten 15-minute intervals:

```bash
uv run scripts/run_discovery_goals.py --provider codex --interval-indexes 0-9 --jobs 2
uv run scripts/run_discovery_combine.py --provider codex
uv run scripts/run_discovery_bridges.py --provider codex
uv run scripts/build_suggestion_inputs.py
uv run scripts/run_discovery_bangers.py --provider codex --jobs 2
uv run scripts/run_discovery_questions.py --provider codex --jobs 2
uv run scripts/run_generic_qa.py --provider codex --interval-indexes 0-9 --qa-types all --jobs 2
```

Or use Claude:

```bash
uv run scripts/run_discovery_goals.py --provider claude --interval-indexes 0-9 --jobs 2
uv run scripts/run_discovery_combine.py --provider claude --force
uv run scripts/run_discovery_bridges.py --provider claude --force
uv run scripts/build_suggestion_inputs.py --discovery-dir discovery_claude_15m
uv run scripts/run_discovery_bangers.py --provider claude --jobs 2
uv run scripts/run_discovery_questions.py --provider claude --jobs 2
uv run scripts/run_generic_qa.py --provider claude --interval-indexes 0-9 --qa-types all --jobs 2
```

## Stage Outputs

### `01_goals`

Generated by:

```bash
uv run scripts/run_discovery_goals.py
```

Writes one file per selected interval:

```text
discovery_codex_15m/01_goals/goal_<interval_index>.json
```

Each run gets an isolated agent workdir by default. For this stage the agent
can see `logs-indexed/` and an empty `agent-output/` directory, then the runner
copies the created goal JSON back into the discovery directory.

Select intervals with:

```bash
--interval-indexes 0,3,10-12
--start 50 --limit 25
```

### `02a_combined`

Generated by:

```bash
uv run scripts/run_discovery_combine.py
```

Reads `01_goals/goal_*.json` and writes:

```text
discovery_codex_15m/02a_combined/combined.json
```

### `02b_bridges`

Generated by:

```bash
uv run scripts/run_discovery_bridges.py
```

Reads `02a_combined/combined.json` and writes:

```text
discovery_codex_15m/02b_bridges/bridges.json
```

This stage looks across all combined goals for broader cross-goal goals, motivations, and competing tensions.

### `02c_suggestion_inputs`

Generated by:

```bash
uv run scripts/build_suggestion_inputs.py
```

Reads `02a_combined/combined.json` and `02b_bridges/bridges.json`, then writes:

```text
discovery_codex_15m/02c_suggestion_inputs/inputs.json
```

This normalizes siloed goals and bridge goals into one compact input list for banger generation. Every row has the same fields: `type`, `name`, `time`, `usefulness`, `confidence`, `disregard`, `context`, `reasoning`, and `description`.

The output is sorted by `time`. For siloed goals, `time` is the earliest source goal timestamp. For bridge goals, `time` is when the bridge first becomes knowable from its connected goals.

### `03_bangers`

Generated by:

```bash
uv run scripts/run_discovery_bangers.py
```

Reads `02c_suggestion_inputs/inputs.json` and writes:

```text
discovery_codex_15m/03_bangers/bangers_<start_input_index>_<end_input_index>.json
```

Run a subset with:

```bash
--combined-indexes 0,4,8-10
```

Despite the option name, banger indexes refer to rows in
`02c_suggestion_inputs/inputs.json` when that file exists.

Run several `02c_suggestion_inputs` in each model call:

```bash
uv run scripts/run_discovery_bangers.py --provider codex --combined-indexes 0-4 --banger-batch-size 5
```

This writes one output file per batch:

```text
discovery_codex_15m/03_bangers/bangers_0_4.json
...
```

Flatten all generated banger opportunities into one chronological list:

```bash
uv run scripts/combine_bangers.py
```

This writes `discovery_codex_15m/03_bangers/sequential_bangers.md` by default.

### `04_questions`

Generated by:

```bash
uv run scripts/run_discovery_questions.py
```

Reads `03_bangers/bangers_*.json` and writes:

```text
discovery_codex_15m/04_questions/question_<combined>_<goal>_<opportunity>.json
discovery_codex_15m/04_questions/final_questions.json
```

`final_questions.json` is the final consolidated artifact.

If a question run is interrupted or only a subset succeeds, rerun the same
command without `--force` to skip completed question files and rebuild
`final_questions.json` from whatever completed files are present.

Each question file stores the exact 100 past context events used for training:

```text
context_events + question -> answer
```

The stored artifact also keeps generation metadata such as `why_it_matters`,
`evidence_grounding`, and `question_basis`.

Export the training-visible JSONL rows, excluding generation metadata:

```bash
uv run scripts/export_training_questions.py \
  --input discovery_codex_15m/04_questions/final_questions.json \
  --output discovery_codex_15m/04_questions/training_questions.jsonl
```

### `10_generic_qa`

Generated by:

```bash
uv run scripts/run_generic_qa.py
```

This is pipeline `1.0`: a standalone generic QA generator that does not depend
on banger suggestions. It runs one QA type per model call, attaches the same
latest-100 indexed past events used by `04_questions`, and writes one
single-thread QA file per interval and QA type:

```text
discovery_codex_15m/10_generic_qa/<qa_type>/qa_<interval_index>.json
discovery_codex_15m/10_generic_qa/final_qa.json
```

Run all built-in QA types for selected intervals:

```bash
uv run scripts/run_generic_qa.py --provider codex --interval-indexes 0-9 --qa-types all --jobs 2
```

Run a smaller focused pass:

```bash
uv run scripts/run_generic_qa.py --provider codex --interval-indexes 0 --qa-types activity_window,predictive_actions
```

Export training-visible rows:

```bash
uv run scripts/export_training_questions.py \
  --input discovery_codex_15m/10_generic_qa/final_qa.json \
  --output discovery_codex_15m/10_generic_qa/training_questions.jsonl
```

### `20_pre_banger_qa`

Generated by:

```bash
uv run scripts/run_pre_banger_qa.py
```

This is pipeline `20`: a standalone pre-banger QA generator anchored on
historical `03_bangers` opportunities. It first runs
`prompts/20_pre_banger_filter.md` to create a prompt-ranked seed set, using
the model to score `user_value` and `intervention_value_now`. The ranking
distinguishes "this would be useful" from "this is a good moment for the
assistant to surface it." It then generates Q/A rows that teach the user model
when proactive help has marginal value now, when the assistant should wait, and
when the user is likely to do the next useful thing themselves.

Outputs:

```text
discovery_codex_15m/20_pre_banger_qa/seed_rankings.json
discovery_codex_15m/20_pre_banger_qa/<qa_type>/qa_<seed_id>.json
discovery_codex_15m/20_pre_banger_qa/final_qa.json
```

Run all built-in QA types for the top prompt-ranked seeds:

```bash
uv run scripts/run_pre_banger_qa.py --provider codex --limit 10 --qa-types all --jobs 2
```

Shard by source interval, similar to pipeline `10`:

```bash
uv run scripts/run_pre_banger_qa.py --provider codex --interval-indexes 40-49 --qa-types timing,curiosity --jobs 2
```

When `--interval-indexes` is supplied, pipeline `20` keeps only banger seeds
whose `banger_timestamp` falls inside the selected interval rows. The default
ranking file is also interval-specific, such as
`seed_rankings_intervals_40-49.json`, and the final aggregate is
`final_qa_intervals_40-49.json`, so interval shards can run in parallel without
sharing one ranking or final output.

Run a smaller focused pass:

```bash
uv run scripts/run_pre_banger_qa.py \
  --provider codex \
  --seed-ids 29_0_0,25_0_0 \
  --qa-types curiosity,engagement,threaded_mix
```

The single-turn QA types write top-level `qa_pairs`. The `threaded_mix` type
writes three independent `threads`, each with ordered Q/A pairs that mix
curiosity, timing, surprise, engagement, personal relevance, self-done
likelihood, and wait/surface/stay-quiet judgments.

Preview or regenerate only the seed-ranking prompt:

```bash
uv run scripts/run_pre_banger_qa.py --dry-run --force-seed-filter --print-prompt
```

Export training-visible rows:

```bash
uv run scripts/export_training_questions.py \
  --input discovery_codex_15m/20_pre_banger_qa/final_qa.json \
  --output discovery_codex_15m/20_pre_banger_qa/training_questions.jsonl
```

For interval shards, point export at the interval-specific final file:

```bash
uv run scripts/export_training_questions.py \
  --input discovery_codex_15m/20_pre_banger_qa/final_qa_intervals_40-49.json \
  --output discovery_codex_15m/20_pre_banger_qa/training_questions_intervals_40-49.jsonl
```

## Common Options

Use a different output root:

```bash
--discovery-dir /path/to/discovery_run
```

Use a different interval size:

```bash
--interval-minutes 30
```

Preview a stage without invoking the model:

```bash
--dry-run
```

Print the full rendered prompt during a dry run:

```bash
--dry-run --print-prompt
```

Overwrite existing outputs:

```bash
--force
```

Continue after per-item failures:

```bash
--continue-on-error
```

Run multiple selected model calls concurrently:

```bash
--jobs 4
```

## Inspect Outputs

Serve the local discovery viewer:

```bash
uv run scripts/serve_discovery_viewer.py --discovery-dir discovery_codex_15m
```

The viewer exposes tabs for per-interval goals, combined goals, banger
opportunities, and generated question sets.

## Quick Smoke Test

After indexing and interval creation, preview one interval through the first
stage:

```bash
uv run scripts/run_discovery_goals.py --provider codex --interval-indexes 0 --dry-run
```

Then run a real small pass:

```bash
uv run scripts/run_discovery_goals.py --provider codex --interval-indexes 0
uv run scripts/run_discovery_combine.py --provider codex --force
uv run scripts/run_discovery_bridges.py --provider codex --force
uv run scripts/build_suggestion_inputs.py --discovery-dir discovery_codex_15m
uv run scripts/run_discovery_bangers.py --provider codex --combined-indexes 0
uv run scripts/run_discovery_questions.py --provider codex --combined-indexes 0
```
